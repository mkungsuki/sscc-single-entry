# Scout Brief: KPHIS → SSCC Pre-fill (สำหรับ Claude Code เครื่องที่เข้าถึง KPHIS)

**Date:** 2026-08-24
**Raw request:** "พยาบาลถามว่าพอจะทำให้มันกรอกให้ระดับนึงก่อนได้ไหม เพราะบางอันเขากรอกใน kphis แล้ว"

ไฟล์นี้คือ "ใบสั่งงานสำรวจหน้างาน" — เครื่องที่อ่านไฟล์นี้คือเครื่องที่เปิด KPHIS ได้จริง
เป้าหมายของรอบนี้คือ**ทำแผนที่ข้อมูล ไม่ใช่สร้างฟีเจอร์** — ห้ามเริ่มเขียน userscript/endpoint จริงจนกว่าแผนที่จะเสร็จและถูกรีวิว

---

## ⚠️ กติกาความปลอดภัย (อ่านก่อนทำอะไรทั้งสิ้น — ทุกข้อคือ hard rule)

1. **ห้ามเปิด/อ่านไฟล์หรือ response ที่มีข้อมูลคนไข้จริง** — ถ้าจำเป็นต้องดูโครงจาก response จริง
   ให้ mask ค่าตั้งแต่ในสคริปต์ (ดู template ข้างล่าง) แล้ว**ให้คนเปิดตาดู output ก่อน**ค่อยอ่าน
2. **repo นี้ public บน GitHub** — ทุกอย่างที่ commit = สาธารณะ ดังนั้นห้ามมี:
   ค่าจริงของคนไข้ทุกชนิด (ชื่อ/HN/AN/เลขบัตร/วันเกิด/ที่อยู่), ชื่อ-นามสกุลเจ้าหน้าที่,
   hostname/IP ภายใน รพ. (เขียนเป็น `KPHIS_HOST` เสมอ), screenshot หน้าจอที่มีข้อมูลจริง
   ตัวอย่างค่าในเอกสารให้ใช้ค่าปลอมล้วนๆ (`สมชาย ทดสอบ`, `HN 0000000`)
3. **อ่านอย่างเดียว** — สคริปต์ทุกตัวห้ามมี request ที่เป็นการเขียน/บันทึก (POST/save/delete/
   confirm/update) ไปหา KPHIS โดยเด็ดขาด และห้ามกดปุ่มใดๆ บน KPHIS ที่เป็นการบันทึกข้อมูล
4. **Claude Code เขียนสคริปต์ได้เฉพาะ read-only ตาม template ใน brief นี้** และ
   **ห้ามรันอะไรที่ตัวเองเขียนโดยไม่ให้คนดูโค้ดก่อน** — คนเป็นผู้วางสคริปต์ใน Console/Tampermonkey เอง
5. ก่อน commit อะไรกลับขึ้น repo: ไล่อ่านไฟล์ทั้งไฟล์ด้วยตาคน 1 รอบ เช็คตามข้อ 2

## บริบท (สิ่งที่ตัดสินใจล็อกไว้แล้ว — ห้าม re-debate)

- **SSCC** (repo นี้) = โปรแกรมกรอก stroke registry บนเครื่องพยาบาล รันที่ `localhost:8547`
  ฟอร์ม 136 ฟิลด์อยู่ใน `app/schema/sscc_fields.json`
- **เครื่องเดียวกัน**: พยาบาลเปิด KPHIS และ SSCC บนคอมเครื่องเดียวกัน
- **Flow ที่จะสร้าง (หลัง scout เสร็จ)**: ปุ่ม "ส่งเข้า SSCC" (userscript บนหน้า KPHIS)
  → `POST localhost:8547/api/prefill` → สร้าง**เคสร่าง**ที่เติม Tier 1+2 ไว้
  → พยาบาลเปิด SSCC เติมส่วนคลินิกเอง → ส่งตามปกติ
  → กันซ้ำ: HN เดิมมีร่างอยู่ = เติมเฉพาะช่องว่างของร่างเดิม ห้ามทับค่าที่มือกรอก
  → ทุกช่องที่เครื่องเติมติดธง "มาจาก KPHIS" ให้ฟอร์มโชว์ว่าช่องไหนต้องตรวจทาน
- **Scope**: Tier 1+2 เท่านั้น (ดูตารางล่าง) — ข้อมูลคลินิก (NIHSS, เวลา CT ฯลฯ) พยาบาลกรอกเองต่อไป
- ยึดหลัก AI-IPD-SUMMARY เดิม: browser-only, ทำงานใน session ที่ user login เอง,
  human-in-the-loop, ไม่แตะ backend/DB ของ รพ.

## วิธีทำงาน (เรียงลำดับ)

1. **สัมภาษณ์พยาบาลก่อนแกะจอ** — ให้เขาไล่ทีละฟิลด์ในตารางข้างบนว่า
   "ปกติช่องนี้พี่เปิดดูจากหน้าไหน" → ได้รายชื่อหน้า KPHIS ที่ต้องส่อง (คาดว่าหลายหน้า
   ตามนิสัย HIS ที่ข้อมูลกระจาย) + รู้เลยว่าฟิลด์ไหนพยาบาลก็ต้องเดา/หาเอง
2. เปิดหน้า KPHIS ทีละหน้า (คน login + navigate เอง) แล้วใช้ structure-peek script
   ส่องว่าข้อมูลมาทาง DOM หรือ XHR/fetch, selector/endpoint อะไร
3. จดลง field map ทันทีทีละหน้า อย่ารอจดรวมท้ายวัน

## Structure-peek script — กติกา template

สคริปต์ที่ Claude Code เขียนให้คนวางใน Console ต้องเป็นไปตามนี้ทุกตัว:

- ห้ามยิง network request ใดๆ เพิ่มเอง (สังเกต XHR ที่หน้าเว็บยิงเองผ่าน DevTools Network tab แทน)
- ห้ามแตะ event ที่ trigger การบันทึก
- **mask ค่าตั้งแต่ในสคริปต์** — ห้าม print ค่าจริง ให้รายงานเป็นชนิด+ความยาว เช่น
  `ThaiText[7]`, `Digits[13]`, `Date"DD/MM/YYYY(พ.ศ.)"`, `Empty`
  ตัวเลือก (select/radio) รายงาน**รายการ option ทั้งหมด**ได้ (เป็นโครงสร้างหน้า ไม่ใช่ข้อมูลคนไข้)
  แต่**ห้าม**รายงานว่าเคสนี้เลือกอันไหนอยู่
- output จบใน console เท่านั้น ห้าม auto-download/ส่งออกไปไหน

- ห้ามเขียน userscript ตัวจริง / แก้โค้ดใน `app/` — รอ field map ผ่านรีวิวก่อน
