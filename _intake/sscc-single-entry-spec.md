# Spec Sheet: sscc-single-entry (โปรแกรมกรอกครั้งเดียว SSCC Stroke)

**Date:** 2026-07-13
**Raw request:** "ที่ รพ มีปัญหาในการกรอกข้อมูลเข้า SSCC stroke เพราะมันทำงานซ้ำซ้อน ตอนแรกเราจะแก้ปัญหาด้วย bundle แล้วให้พยาบาลกรอกไปแต่เจออีกอันคือเขาเหมือนต้องกรอกสองรอบเพราะกรอกในเวป SSCC เพื่อทำ KPI ส่งองคกร แล้วก็ต้องกรอก excel เพื่อเก็บไว้ทำวิจัยหรือ KPI รพ อีกต่อ แถมการดึง HOSXP ก็น่าจะยากเพราะก่อนหน้านี้ก็ไม่ได้ทำ paperless ที่ดึงข้อมูลที่ในนี้ต้องการได้ทุกอันอีกห มีข้อเสนออะไรไหม"

## Problem
- โจทย์: พยาบาลกรอกข้อมูลผู้ป่วย stroke **ครั้งเดียว** ในโปรแกรมของหน่วยงาน แล้วโปรแกรมไปกรอกเว็บ SSCC ให้อัตโนมัติ (พยาบาลตรวจก่อนกดบันทึก) พร้อมเก็บฐานข้อมูลของ รพ. เอง ที่รองรับฟิลด์เพิ่มเติมนอกเหนือจาก SSCC
- ผู้ใช้: พยาบาล stroke unit รพ.ชุมแพ (กรอก) / ทีมแพทย์-พยาบาลที่ทำวิจัยและ KPI (ใช้ข้อมูล)
- ทำไมต้องสร้าง: ปัจจุบันกรอกซ้ำซ้อน (เว็บ SSCC + บันทึกแยกไม่มีระบบ) และหน้ากรอก SSCC งุ่มง่าม — ปุ่ม "เพิ่ม" รับแค่ A1-A6 แล้วต้องวนกลับเข้าโหมดแก้ไข ไล่กรอกทีละแท็บ (8 แท็บ) กดบันทึกทีละแท็บ; ต้องการเก็บฟิลด์ที่ SSCC ไม่มีด้วย จะได้ไม่ต้องรื้อชาร์ตย้อนหลัง
- ปริมาณงาน: 5–10 เคส/วัน

## I/O Contract
- **Input:** พยาบาลกรอกฟอร์มเดียวในโปรแกรม เรียงลำดับตามชาร์ต — ครอบคลุมชุดฟิลด์ SSCC ทั้งหมด (149 คอลัมน์ แท็บ A1–F1) + ฟิลด์ custom ของ รพ. (เพิ่มภายหลังได้)
- **Output 1:** กรอกเว็บ SSCC อัตโนมัติ — สร้างเคสใหม่ (ฟอร์มสั้น A1-A6) → ไล่เติมทุกแท็บ → **หยุดให้พยาบาลตรวจก่อนกดบันทึกแต่ละแท็บ** (ไม่ยิงส่งเงียบๆ)
- **Output 2:** ไฟล์ Excel/CSV master ในเครื่อง — 1 แถว/เคส ต่อท้ายอัตโนมัติ เลือกที่เซฟได้
- **Success criteria:**
  - กรอก 1 เคส ที่เดียว ครั้งเดียว — ไม่มีการกรอกซ้ำอีกฝั่ง
  - ข้อมูลใน Excel ตรงกับใน SSCC (ตรวจทานได้ผ่านไฟล์ export ของ SSCC)
  - พยาบาลใช้เองได้โดยไม่ต้องมี IT ประกบ
  - เพิ่มฟิลด์ใหม่ได้เองโดยไม่ต้องแก้โค้ด

- **pricing_required:** false

## Constraints
- License: อะไรก็ได้ (open-source components OK)
- Stack: อิสระ — เครื่อง Windows ของหน่วยงาน ลงโปรแกรมได้เองไม่ต้องขอ IT
- Hosting: local เครื่องเดียวทั้งหมด ไม่มี server — ลดภาระ PDPA (ข้อมูลมีเลขบัตร ปชช. + ชื่อผู้ป่วย)
- Login SSCC: username + password เท่านั้น ไม่มี CAPTCHA/OTP
- Timeline: ไม่เร่งเป็นทางการ
- Budget: ไม่มี (ทำเอง)

## Non-functional Requirements
- Performance: กรอก 1 เคสจบภายในเวลาไม่มากกว่าที่เคยกรอกเว็บ SSCC ตรงๆ
- Scalability: 5–10 เคส/วัน เครื่องเดียว ผู้ใช้หลักคือพยาบาลหน่วยงานเดียว — ไม่ต้องรองรับ multi-user
- Reliability: ไฟล์ master ต้องมี backup อัตโนมัติ (กันไฟล์พัง/เผลอลบ)
- Security: ไม่เก็บ password SSCC ในโปรแกรม — พยาบาล login เองทุกครั้ง; ข้อมูลผู้ป่วยอยู่ในเครื่องเดียว
- Observability: log ง่ายๆ ว่าเคสไหนส่งเข้า SSCC แล้ว/ยัง

## Architecture Decisions Already Made (ห้าม downstream re-debate)
- **กรอกครั้งเดียวที่โปรแกรมเราคือหัวใจ** — ไม่ใช่แค่ท่อ export: probe ปิดข้อ "export อย่างเดียวพอไหม" → ไม่พอ เพราะต้องเก็บฟิลด์ที่ SSCC ไม่มี ไม่งั้นต้องรื้อชาร์ตกรอกเพิ่มทีหลัง
- **Auto-fill แบบมีคนตรวจ** — โปรแกรมเปิด Chrome ให้ พยาบาล login เอง โปรแกรมเติมฟอร์ม หยุดรอตรวจก่อนกดบันทึกแต่ละแท็บ: ปิดข้อ "ส่งอัตโนมัติ 100%" → เลือกแบบตรวจก่อน เพราะเป็นข้อมูลส่งองค์กรภายนอก
- **ไม่เก็บ credentials** — login มือทุกครั้ง: ปลอดภัยกว่า และไม่ติดอะไรเพราะไม่มี CAPTCHA
- **ฟิลด์ custom เป็น config-driven** — เพิ่มชื่อฟิลด์+ชนิดข้อมูลในหน้าตั้งค่า/ไฟล์ตั้งค่า แล้วโผล่ทั้งฟอร์มและ Excel อัตโนมัติ: ปิดข้อ "รอสรุปรายการฟิลด์ก่อน" → ไม่รอ เริ่มด้วยชุด SSCC แล้วเพิ่มทีหลัง
- **ข้อมูลเก่า bootstrap จาก export** — SSCC export (CSV 149 คอลัมน์ ~4,000 เคส) ใช้ตั้งต้นฐานวิจัย + ใช้ reconcile ความครบถ้วน ไม่ต้องกรอกย้อน
- **HOSXP integration = out of scope** — รพ. ไม่ได้ paperless ครบ ดึงไม่ได้ทุกฟิลด์ ไม่คุ้มทำตอนนี้

## Priority Tiers
- **P0 (must):**
  - ฟอร์มกรอกครบชุดฟิลด์ SSCC (A1–F1) เรียงตามลำดับการรื้อชาร์ต + validation พื้นฐาน
  - เซฟลงไฟล์ master (Excel/CSV) ในเครื่อง + backup อัตโนมัติ
  - Auto-fill เว็บ SSCC: สร้างเคส (A1-A6) → เติมทุกแท็บ → รอตรวจก่อนบันทึกแต่ละแท็บ
  - สถานะต่อเคส: ร่าง / ส่ง SSCC แล้ว
- **P1 (should):**
  - นำเข้าข้อมูลเก่าจากไฟล์ export SSCC (~4,000 เคส) เข้าฐานวิจัย
  - กลไกเพิ่มฟิลด์ custom (config-driven)
  - เครื่องมือ reconcile: เทียบไฟล์ master กับ export SSCC หาเคสตกหล่น
- **P2 (nice):**
  - สรุป KPI อัตโนมัติ (เช่น door-to-needle, % stroke unit, % swallowing screen 72 ชม.)
  - รองรับหลายเครื่อง / shared drive
  - โมดูลติดตาม 90 วัน (mRS 90d)
