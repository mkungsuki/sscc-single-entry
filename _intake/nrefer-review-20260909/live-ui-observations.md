# nRefer: หลักฐานจากการดู UI ร่วมกับผู้ใช้

2026-09-09 — ใช้ Codex in-app browser; เครื่องมือเชื่อม Edge ไม่ได้ในรอบนี้

## Login

- กดปุ่มเข้าสู่ระบบด้วย ThaiID จากหน้า nRefer แล้วถึงหน้า QR ของกรมการปกครอง
- หลังผู้ใช้สแกนครั้งแรก กลับมาหน้า callback ของ nRefer และแสดงข้อความ `Not found any user` เป็นข้อความของแอป ไม่ใช่หน้า HTTP 404 ที่ตรวจยืนยันได้
- ผู้ใช้แจ้งว่าบัญชีเข้าได้ตามปกติในหลายเบราว์เซอร์
- ต่อมาเห็นหน้า QR รอบใหม่ และผู้ใช้แจ้งว่าเข้าได้ ตรวจ UI พบหน้าทะเบียน DMIS พร้อมข้อมูลจริง จึงยืนยันว่า session นี้เข้าถึงทะเบียนได้แล้ว
- ไม่ได้แก้ production code, launch flags หรือ inject token ระหว่างการสังเกตนี้ ไม่ทราบทุก interaction ที่ผู้ใช้ทำเองระหว่างรอบ จึงยังระบุสาเหตุที่รอบแรกไม่ผ่านไม่ได้
- ผลนี้ไม่สนับสนุนข้อสรุปว่าไม่มีบัญชี หรือว่า browser automation ถูกบล็อกเสมอ และยังไม่ได้ reproduce/อธิบาย TS 027 ใน Edge เดิม

## ฟอร์มเพิ่มข้อมูลจริง

เปิด Add new จากทะเบียนเท่านั้น ไม่พิมพ์ข้อมูลผู้ป่วย ไม่กดบันทึก ไม่เรียก API เขียนตรง และไม่ได้ตรวจ network จึงไม่อ้างจำนวน write request ที่ server ได้รับ

สิ่งที่เห็นจาก accessibility UI หลังเปิดฟอร์ม:

1. หัวฟอร์ม `เพิ่มข้อมูล หน่วยงาน: โรงพยาบาลชุมแพ`
2. Diagnosis ที่แสดงในรอบนี้เป็น `S720 Fracture around the Hip`; Diagnosis Group เป็น `Fracture around Hip, 3` และ **disabled** ไม่ใช่ select ที่ผู้ใช้เลือกได้อิสระ
3. รายการ Diagnosis dropdown มี I63–I69, I60–I62 และกลุ่มบาดเจ็บ/hip แต่ **ไม่พบ G45 ในรายการที่แสดง** ขณะเดียวกันมีช่องข้อความ ICD แยกอยู่ จึงยังไม่ได้สรุปว่าเว็บไม่รับ G45 ทุกวิธี
4. ผู้นำส่งแสดง `EMS รพ.` อยู่ก่อนกรอก รอบนี้ยังพิสูจน์ไม่ได้ว่ามาจากค่าเริ่มต้นถาวรหรือ state ก่อนหน้า
5. rt-PA/CT/Stroke Unit/ผ่าตัด แสดง `ไม่ทราบ`; ช่องวันเวลาที่เกี่ยวข้อง disabled
6. mRS แสดง Select ทั้งสองช่อง, ward แสดงเลือก..., ปุ่มบันทึก disabled เมื่อฟอร์มยังว่าง

## ผลต่อ review/แผน

- `fill_nrefer.py:172–177` พยายาม select ทุกค่ารวม dmis แต่ของจริง disabled; ต้องตรวจพฤติกรรมหลังเลือก Dx ว่ากลุ่มเปลี่ยนตามหรือไม่ แล้ว readback กลุ่มแทนสมมติว่าเลือกได้อิสระ
- mock มี dmis ที่ enabled และมี G45 เป็นตัวเลือก (`mock_nrefer.py:67–68`) ต่างจากฟอร์มที่เห็นจริง ดังนั้น mock pass ไม่รับรองสองจุดนี้
- ต้องทดสอบความสัมพันธ์ Dx→Group, radio→date enabled และค่าเริ่มต้น/ค่าค้างก่อนรันตัวกรอกจริง
- ยังไม่ได้ทดลองกรอก datepicker/mRS/ward หรือรับรอง Angular model รอบนี้

เอกสารนี้ไม่เก็บชื่อผู้ป่วย เลขประชาชน HN/AN, token, OAuth code หรือ QR session identifiers

## ตรวจต่อ 9–10 กันยายน 2026

ข้อความว่า “ยังไม่ได้ทดลอง” ด้านบนเป็นสถานะรอบแรก; ผลด้านล่างเป็นหลักฐานรอบต่อมา

- เลือก I63 แล้ว Diagnosis Group เปลี่ยนเป็น 2 โดยช่อง group ยัง disabled
- เลือก radio “มี” ของ rt-PA, CT, Stroke Unit และผ่าตัด ทำให้วันเวลาที่เกี่ยวข้องเปิดให้กรอก
- mRS 0 เลือกผ่าน pk-select ได้; ward ต้องตรงชื่อและรหัสจริง ไม่ใช้ prefix ที่อาจเลือกผิดรายการ
- Datepicker: `fill` อย่างเดียวไม่เพียงพอ ต้องพิมพ์วันแบบ dd/mm/พ.ศ. ผ่าน keyboard แล้วออกจากช่อง ตรวจซ้ำโดยเปิดปฏิทินและอ่านวันที่ selected
- วันเกิดสมมติ 04/03/2502 ยืนยันซ้ำวันที่ 10 กันยายน: input แสดงตรง, วัน selected = 4 และหัวปฏิทิน “มีนาคม 2502” แม้ปีนี้ไม่มีใน dropdown ปีที่มีช่วงคงที่ 2549–2579
- หลังผู้ใช้สแกนใหม่วันที่ 10 กันยายน เข้า profile และทะเบียนสำเร็จ โดยไม่ได้แก้หรือฉีด token
- GCS ทดลองด้วยฟอร์มใหม่ ไม่มี HN/AN: พิมพ์ E/V/M 3/4/5 ด้วย keyboard ได้ยอดรวม readonly = 12
- จากนั้นใช้ `fill` + Tab เปลี่ยน E/V/M เป็น 4/5/6: ตัวเลขรายช่องเปลี่ยน แต่ยอดรวมยัง 12 จึงยืนยันว่าการอ่านค่ารายช่องอย่างเดียวไม่พอ
- พิมพ์ใหม่ผ่าน ControlOrMeta+A และ pressSequentially เป็น 2/3/4 ได้ยอดรวม 9; ปรับโปรแกรมให้ใช้ keyboard สำหรับ E/V/M พร้อมอ่านยอดรวมตรวจซ้ำ ไม่มีการปลด readonly
- ก่อนออกจากฟอร์มตรวจว่า HN/AN ว่างและปุ่มบันทึก disabled แล้วกลับทะเบียนโดยไม่กดบันทึก

ข้อจำกัด: รอบ live ใช้ CUA ควบคุมเว็บเพื่อยืนยัน widget ไม่ได้รัน Python worker ทั้งเส้นทางใน Edge และไม่ได้ทดสอบบันทึกจริง; ไม่มีการตรวจ network จึงไม่อ้างหลักฐานระดับ server ว่าจำนวน write เป็นศูนย์ ตัว guard โหมดตรวจฟอร์มของโปรแกรมทดสอบแยกบน localhost
