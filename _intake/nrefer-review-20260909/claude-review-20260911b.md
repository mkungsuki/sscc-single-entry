## ยังไม่ผ่าน / ต้องทำต่อ
1. **P0 ยังไม่ได้ทำ (blocker เดิม)** — `nrefer_ui.fill_form` ยังพิมพ์ HN แล้ว AN **ก่อน** ทุกอย่าง (บรรทัด 184–195) → บั๊ก nRefer จะล็อกช่องวันที่ก่อนโปรแกรมไปถึง = อาการ 8051 เดิมทุกประการ แผนของ codex เองก็เขียนว่า P0 ต้องมาก่อนและ "ยังไม่รับรอง" — งาน Motor ที่ทำก่อนเป็นคำสั่งผู้ใช้ในแชท ไม่ว่ากัน แต่ **งานถัดไปต้องเป็น P0** ตามข้อ 0 ของบรีฟ (ไม่พิมพ์ HN/AN, แถบบอก 3 เรื่อง, ตรวจวันที่ disabled แล้วหยุด)
2. **Motor ในเว็บยังเป็นทางเดินมือ**: พยาบาลต้องเปิดเคสเดิม+แท็บ 7 เองในหน้าต่าง Edge ของโปรแกรมแล้วกดปุ่ม "เติมคะแนนในตารางนี้" — ปลอดภัย แต่ต้องมีเรคคอร์ดหลักบันทึกแล้ว (แท็บ 7 ไม่มีในฟอร์มเพิ่มใหม่) และยังไม่มีตัวค้นเปิดเคสหลังบันทึก (P3) → เขียนไว้ใน README/ข้อความปุ่มให้ชัดว่าลำดับคือ บันทึกหลัก → เปิดเคส → แท็บ 7 → กดปุ่ม
3. เล็กน้อย: `annotate` เขียน `_motor_projection` 20 แถวลงทุกเคสทุกครั้งที่บันทึก แม้ไม่มีคะแนน Motor เลย (Excel ข้าม key ขึ้นต้น `_` อยู่แล้ว ไม่พัง) — ควร annotate เฉพาะเมื่อมีคะแนนอย่างน้อย 1 ส่วน ลดขยะใน data
4. เล็กน้อย: "Ward ปลายทาง — ระบุเฉพาะกรณีจับคู่ชื่อไม่ได้" โผล่ตอนเคสใหม่ที่ยังไม่เลือก B1.1 (เพราะยังจับคู่ไม่ได้) — ควรซ่อนจนกว่า B1.1 จะมีค่าและจับคู่ไม่ได้จริง
5. ต้องรู้ไว้: nRefer ทุกเส้นทางตอนนี้**บังคับมี AN** (`_nrefer_ready`, motor) — พยาบาลต้องกรอก AN ในโปรแกรม ซึ่งถูกหลักแล้ว (nRefer แยกครั้งรักษาด้วย AN) แค่ต้องบอกในคู่มือ
6. แท็บ 4/5 (BI/แผนจำหน่าย) ยังไม่เริ่ม — ตามแผน P1–P4 ของ codex เอง; ยังคงคำถามถึงขอนแก่นข้อ 2–5 ในแผนของเขา

## ข้อสังเกตทางคลินิกที่ต้องรับรู้ (ไม่ใช่บั๊ก)
กติกา "คัดลอกคะแนนแขน/ขา → รากประสาท 5 ระดับ" เป็นคำสั่งของผู้ใช้ codex บันทึกที่มาไว้ชัด (`stroke-limb-copy-v1`) และไม่อ้างว่าเป็น ASIA จริง — ถ้าขอนแก่นหรือกระทรวงใช้ตาราง ASIA นี้วิเคราะห์ SCI ค่าที่กรอกจะดู "ปกติทุกระดับ" สำหรับแขนที่ 5 ซึ่งตรงกับความจริงทางคลินิกของ stroke อยู่แล้ว รับได้
