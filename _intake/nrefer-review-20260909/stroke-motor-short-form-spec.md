# ข้อกำหนดเพิ่มเติม: Motor power แบบ stroke 4 ส่วน

วันที่: 11 กันยายน 2026 · iteration ของแผน nRefer เฟส 2 เดิม

## ข้อตกลงล่าสุดและสิ่งที่ทำแล้ว (แทนข้อเสนอเดิมด้านล่าง)

ผู้ใช้ยืนยันให้คัดลอกคะแนนสรุปเป็นค่าเริ่มต้นตามวิธีรายงานที่ทีมใช้งาน:

- แขนซ้าย/ขวา 0–5 → C5/C6/C7/C8/T1 ด้านเดียวกัน
- ขาซ้าย/ขวา 0–5 → L2/L3/L4/L5/S1 ด้านเดียวกัน
- ไม่ต้องยืนยันผลตรวจห้าท่าทีละกลุ่มก่อนคัดลอก; แก้รายช่องได้ภายหลัง
- ที่มาของกติกาคือคำสั่งผู้ใช้ในงานนี้ ไม่ได้อ้างว่าคะแนนสรุปพิสูจน์ผลตรวจรายกล้ามเนื้อ หรือเป็นข้อกำหนดระดับชาติที่ตรวจสอบแล้ว

เพิ่มในฟอร์มหลักแล้ว: การ์ด 2×2 ใกล้ GCS, ปุ่มคะแนน 0–5, ล้างคะแนนสรุป, รายช่องแบบพับเก็บ, ปุ่มกรอก Motor power ใน nRefer; จอเล็กเรียงการ์ดแนวตั้ง

ข้อมูล: `cf_motor_arm_left/right`, `cf_motor_leg_left/right`; `_motor_overrides` เก็บค่าที่แก้เอง (รวม `unset` เพื่อเว้นว่าง) และ `_motor_projection` เก็บผลกระจายกับที่มา `limb-copy`/`override` ตามกติกา `stroke-limb-copy-v1` โดยคำนวณใหม่ฝั่งเซิร์ฟเวอร์ ค่าที่แก้รายช่องไม่ถูกทับเมื่อเปลี่ยนคะแนนสรุป

บันทึกร่างได้แม้ยังไม่ครบ; เลข 0 ต่างจากค่าว่าง ตัวกรอกเว็บต้องมีค่าครบ 20 ช่องก่อนเริ่ม เพื่อไม่ปล่อย default 5 ของเว็บในส่วนที่ต้นทางยังว่าง

ขั้นตอนเว็บในรุ่นนี้: กดปุ่ม Motor → เปิดเคสเดิมและแท็บ 7 ในหน้าต่าง nRefer ของโปรแกรม → กด “เติมคะแนนในตารางนี้” → โปรแกรมตรวจ HN/AN แบบไม่ส่งค่าออก log แล้วกด native radios/readback ครบ 20 ช่อง → ผู้ใช้ตรวจวันที่/เวลา/ผู้ประเมินและกดบันทึกเอง ไม่มีการเลือกวันประเมินหรือสร้างผลย้อนหลังให้ ไม่เปลี่ยนสถานะการบันทึกข้อมูลหลักของเคส

ข้อจำกัด: ยังให้ผู้ใช้เปิดรายการและเลือกชุดประเมินเอง ไม่ได้ทำตัวค้นหารายการหลังบันทึกสำหรับ pipeline เฟส 2 ทั้งชุด การตรวจตัวกรอก Motor ใช้หน้าจำลองที่อิงชื่อ radio/value จาก JS สาธารณะ `chunk-UIVIL3PE.js` (za/ja/Ua) ยังไม่ได้กรอกหรือบันทึก Motor ในเคสจริง

## ประวัติข้อเสนอเดิม (ยกเลิกเงื่อนไขยืนยันผลรายท่าแล้ว)

## คำขอและคำตอบผู้ใช้

> motor power นี่เพื่อช่วยพยาบาล เพราะของเรามันเป็ฯ stroke มันไม่ต้องละเอียดถึง ระดับแบบ spine ทำให้เขากดแบบ stroke แล้วฟอร์มแปลผลไปกดให้หมดในเวปตามหลักได้ไหม

ผู้ใช้ยืนยัน input: **Motor power 0–5 แยกแขนขา 4 ส่วน** ไม่ใช่ motor arm/leg ของ NIHSS

## เป้าหมาย

ลดจำนวนการกดและศัพท์ระดับรากประสาทบนหน้าหลัก ให้พยาบาลเริ่มที่แขนซ้าย/ขวา ขาซ้าย/ขวา แล้วเตรียมข้อมูลกรอกเว็บตามผลตรวจที่มีจริง โปรแกรมไม่กด Save และไม่ตีความค่าที่ไม่ได้ตรวจ

## ข้อจำกัดของการแปลง

ตารางปลายทางแยก key muscles: แขน C5/C6/C7/C8/T1 และขา L2/L3/L4/L5/S1 ทั้งสองด้าน ตาม [ASIA/ISNCSCI worksheet 2026](https://asia-spinalinjury.org/wp-content/uploads/2026/07/ASIA-ISCOS-Worksheet-Both-Sides_4_2026.pdf)

คะแนนสรุปของแขนหรือขาอย่างเดียวไม่บอกว่ารายกล้ามเนื้อทั้งห้ามีคะแนนเท่ากัน จึงไม่สามารถยืนยันผลรายข้อจากสี่ค่าล้วน ๆ ได้ โดยเฉพาะกล้ามเนื้อคนละตำแหน่ง เช่น งอข้อศอกกับงอนิ้ว

ใช้การกรอกแบบกลุ่มได้เมื่อผู้ตรวจยืนยันว่ารายการตรวจทั้งห้าได้คะแนนนั้นจริง นี่คือการบันทึกผลหลายรายการที่เท่ากัน ไม่ใช่สูตรแปลงคะแนนสรุป stroke เป็นคะแนน ASIA หรือการจัดระดับ AIS

## หน้าจอที่เสนอ

- สี่ส่วน: แขนซ้าย แขนขวา ขาซ้าย ขาขวา; ปุ่ม 0–5 เริ่มว่าง
- คะแนนสรุปเก็บแยกจากค่ารายกล้ามเนื้อ ไม่ทำให้ 20 ช่องพร้อมส่งโดยอัตโนมัติ
- แต่ละส่วนมีตัวเลือก “ตรวจแล้ว: ทั้ง 5 ท่าด้านล่างได้คะแนนนี้เท่ากัน” ไม่ติ๊กให้ล่วงหน้า
- ถ้ายืนยันจริง ให้ขยายค่าเท่ากันไปห้ารายการในส่วนนั้น และเก็บที่มาว่าเป็นผลที่ผู้ตรวจยืนยันแบบกลุ่ม
- ถ้าค่าไม่เท่ากัน เปิด “ดู 5 ท่า / ระบุค่าที่ต่างกัน” ด้วยชื่อการเคลื่อนไหวภาษาไทย พร้อมรหัสระดับกำกับ
- ถ้าไม่ได้ตรวจ/ประเมินไม่ได้ คงเป็น unknown; ไม่แทนด้วย 0 หรือ 5 และไม่ส่งช่องนั้นเสมือนมีผล
- ปุ่มย้อนกลับและ preview แสดงค่าที่จะส่ง; หลังเปลี่ยนคะแนนที่เคยยืนยันแบบกลุ่มต้องยืนยันใหม่
- กรอกเว็บผ่าน UI และ readback เฉพาะค่าที่มีหลักฐาน; พยาบาลเป็นผู้กดบันทึก

## เกณฑ์ก่อน implement ตัวกรอก Motor power

1. กรอกสี่ค่าสรุปโดยไม่ยืนยันผลรายท่า ต้องไม่มีคะแนนรายข้อถูกสร้างหรือส่ง
2. ยืนยันผลเท่ากันเฉพาะส่วนหนึ่ง ส่งได้เฉพาะห้าข้อของด้านนั้น; ซ้าย/ขวาไม่สลับ
3. แก้ค่าต่างกันเฉพาะกล้ามเนื้อ ต้องเก็บข้ออื่นถูกต้องและไม่ทับด้วย summary
4. missing, 0, 5 แยกกันชัดเจน; ไม่ตีความแขนข้างไม่อ่อนแรงว่า 5 ทุกข้อโดยอัตโนมัติ
5. ไม่อ้างว่าทำ ISNCSCI/AIS ครบจากหน้าสรุปสี่ส่วน
6. ยังต้องยืนยันความจำเป็นของแท็บ 7 ใน workflow โรงพยาบาลก่อนกำหนดเป็นขั้นบังคับ; ไม่ขวาง BI/แผนจำหน่าย
